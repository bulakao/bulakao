## Evidence Limits

## User Goal

A qualified business owner should understand that Bulakao can start with one messy workflow, but the relationship can grow into ongoing improvements, integrations, dashboards, AI support, and maintenance.

## Research Signals

- Symph's The Agency pairs "fast first version" with "monthly improvements" and a subscription model. This makes first build feel like an entry point, not a one-off.
- Socia positions around custom business systems and automation that reduce manual work, speed up sales, and scale with the business.
- Retool frames internal tools as a path from one app to operational scale, with examples like dashboards, inventory trackers, reporting, approval workflows, and AI routing.
- Airtable frames workflow management around structure, visibility, automation, bottlenecks, and continuous improvement.

## Current Page Risk

Before this change, the page over-indexed on:

- one messy process
- smallest useful tool
- first usable version
- no big proposal
- rough message CTA

That made the page approachable, but it risked implying:

- Bulakao only does one-off small projects.
- The product stops after v1.
- The service is a tiny-build offer, not a long-term custom software partner.
- Monthly improvements and system ownership are secondary.

## Recommendation

Keep "start small" as the conversion strategy, but make the middle of the page explain the larger path:

1. Start with one workflow.
2. Use it with the team.
3. Keep improving the system.

The strongest line:

> The first build is the starting point, not the ceiling.

## Changes Made

- Updated page meta description from "clear first step" to "first useful tool, then keeps improving the system."
- Updated hero support copy to include ongoing improvement.
- Reframed `What you get` into `Growth path`.
- Replaced "A first screen. A first flow. A first usable version." with "Start with one workflow. Grow into the system."
- Rewrote the three deliverables as Start / Use / Improve.
- Updated Work section copy to say focused first builds can become the operating system around the work.
- Updated FAQ answers to make monthly improvement and long-term growth clearer.
- Updated Start small copy so the final CTA still feels low-friction but no longer sounds like a one-off.

## Accessibility Notes

- The change is mostly copy and structure, so visual accessibility risk is low.
- The existing three-card deliverable pattern remains semantically readable as separate articles.
- Screenshot-only review cannot confirm keyboard flow or screen-reader announcement quality.

## Next Recommendation

Later, consider adding a small "How it grows" visual or plan comparison only after the page has real examples. For now, the copy change keeps the page simple while fixing the strategic ambiguity.
